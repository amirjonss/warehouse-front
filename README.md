# Wirehouse — фронт складского учёта (демо для показа клиенту)

Кликабельный прототип оптового склада: маргарин, сгущённое молоко, начинки, масло
сливочное и подсолнечное. Данные демонстрационные, бэкенда нет.

## Запуск

```bash
npm install --prefix wirehouse-front && npm run dev --prefix wirehouse-front
```

Откроется на http://localhost:5173

## Что показывать клиенту

1. **Дашборд** — выручка за день, прибыль в двух валютах, долги, курсовая разница и
   уступки отдельной строкой, партии с истекающим сроком, что пора закупать.
2. **Остатки** → вкладка «По партиям» — у каждой партии свой срок годности и своя
   себестоимость с курсом закупки; просрочка подсвечена.
3. **Новая отгрузка** — добавьте долларовый и сумовой товар в одну накладную: два итога,
   прибыль по каждой строке в валюте её закупки, видно из каких партий уйдёт товар (FEFO).
4. **Приём оплаты** — у клиента долг «3 601 $ + 1 228 000 сўм», платит одним сумовым
   платежом: система заранее показывает, что закроется, какая будет курсовая разница и
   уступка по курсу.
5. **Печать накладной** — два итога, сумма прописью по каждой валюте, пересчёт долларовой
   части в сумы и оговорка про оплату по курсу дня платежа.
6. **Долги** — долг по валютам товара, оценка в сумах по курсу дня, курсовая разница по
   каждому клиенту, кто вышел за лимит.
7. **Смена роли** — выйти и войти продавцом: закупочные цены и разделы прихода исчезают.

Кнопка **«Сброс демо»** в левом нижнем углу возвращает данные в исходное состояние.

## Мультивалютность

Главное правило: **валюта следует за товаром**. Доллар пришёл — доллар и уходит; сум
пришёл — сум и уходит. Ни клиент, ни накладная валюту не выбирают.

| Что | Где живёт |
| --- | --- |
| Валюта прайса товара | `product.currency` — импорт в долларах, местное масло в сумах |
| Валюта расчётов с поставщиком | `partner.currency` — определяет валюту прихода и партии |
| Валюта строки продажи | берётся из товара, менять нельзя |
| Итоги накладной | `sale.totals = { USD, UZS }` — два итога, а не один |
| Курсы дня | `rates[].buy` и `rates[].sell` — как на табличке обменника |
| Курсы документа | `sale.rateBuy` (оценка) и `sale.rateSell` (база для курсовой разницы) |
| Себестоимость партии | `batch.purchasePrice + currency + rate` → `costBase` в сумах |
| Кредитный лимит | один, в сумах: долг бывает сразу в двух валютах |

**Какой курс когда:** клиент платит сумами за долларовый товар — по курсу **продажи**;
платит долларами за сумовой товар — по курсу **покупки**; приход импорта и оценка склада —
по **покупке**. Всегда тот, что выгоден складу; разница между курсами — доход от обмена.

### Как это работает

**Накладная может быть смешанной.** Долларовые позиции суммируются отдельно, сумовые
отдельно — как в бумажной накладной:

```
evro 82/20   5 × 10,00 $ = 50,00 $
evro 72/20   5 ×  5,00 $ = 25,00 $
                   итого:  75,00 $
evro 40/20   7 × 60 000  = 420 000 сўм
                   итого:  420 000 сўм
```

**Долг возникает в тех же валютах.** Взял на 75 $ — вернёт 75 $, независимо от курса.
Взял на 420 000 сўм — вернёт 420 000 сўм.

**Платить можно чем угодно.** Платёж гасит сначала долг в своей валюте, потом переходит
на вторую по курсу оплаты. Клиент с долгом «75 $ + 420 000 сўм» может закрыть всё одним
сумовым платежом — система покажет заранее, что и на сколько закроется.

**Прибыль считается в валюте закупки** той партии, которая реально ушла по FEFO. Товар
куплен за доллары и продан за сумы — прибыль в долларах (`выручка / курс − закуп`). Куплен
за сумы, продан за доллары — прибыль в сумах (`выручка × курс − закуп`). Рядом всегда
лежит приведённая сумовая оценка: сложить две валюты можно только через курс.

### Три вещи, которые считаются отдельно от маржи

- **Курсовая разница** (`fxDiff`) — долларовый долг гасится позже, когда курс уже другой.
  Сравниваются однородные курсы: продажа против продажи, покупка против покупки.
- **Доход от обмена** (`spread`) — разница между курсом продажи и курсом покупки на день
  оплаты, умноженная на сумму, которая реально прошла конвертацию.
- **Уступка по курсу** (`concession`) — продавец применил курс не тот, что в справочнике.
  Фактически скидка, и её видно отдельной строкой, а не размазанной по марже.
- **Хвосты округления** — остаток долга меньше 1000 сўм гасится автоматически при оплате,
  иначе такие «висяки» копятся и их потом ищут вручную.

Курс фиксируется в документе при проведении и больше не меняется: пересчёт задним числом
сделал бы вчерашние отчёты «плавающими». Курс дня правит администратор в шапке, отклонение
от него в накладной и в оплате подсвечивается.

Все сценарии расчётов с числовыми примерами — в отдельном файле [РАСЧЁТЫ.md](РАСЧЁТЫ.md):
доллар→доллар, доллар→сум и обратно, оплата сразу и в долг, откуда берутся курсовая
разница и уступка.

## Устройство проекта

```
src/
  data/mock.js        генератор демо-данных (курсы, товары, партии, документы за ~90 дней)
  stores/warehouse.js состояние склада и бизнес-логика: FEFO, остатки, курсы,
                      partnerLedger — гашение долгов и курсовые разницы
  stores/auth.js      вход и права ролей
  views/              экраны, по одному на маршрут
  components/         оболочка, модалка, график, плитки, курс в шапке
  utils/format.js     деньги в двух валютах, конвертация, даты, склонения, статусы
```

### Главный принцип модели

Остаток нигде не хранится числом. Единственный источник правды — журнал движений
`movements`; остатки по товарам и партиям считаются из него. То же и с долгом: он не
хранится полем, а получается из накладных и платежей в `partnerLedger()`. Когда появится
бэкенд, структура данных не изменится — фронт останется прежним.

### Демо-данные

Генерируются при первом запуске от текущей даты и сохраняются в localStorage, поэтому
созданные вами документы не пропадают при перезагрузке. Если данные «старше» суток,
они пересобираются, чтобы на дашборде всегда были сегодняшние продажи.

## Чего в демо намеренно нет

Инвентаризация, возвраты, резервирование под заказ, себестоимость по FIFO, несколько
складов, отчёты в Excel, интеграции. Всё это надстройки над теми же сущностями и
добавляется поверх текущей модели.
